# Ripley Safaris — website

Multi-page static website (HTML · CSS · JavaScript) built with **Vite**. No server, framework or database is required in production — the build output is plain files you can host anywhere.

* **Pages:** Home, Packages, Gallery and 20 species pages (`animals/*.html`)
* **Motion:** GSAP + ScrollTrigger (replaces AOS) · **Icons:** Lucide (inlined SVG at build time) · **Fonts:** Cormorant Garamond + Jost, self-hosted
* **Themes:** automatic dark/light from the visitor's OS, with a manual switch remembered in `localStorage`
* **Signature detail:** the rifle-scope cursor (`src/js/scope.js`, `src/css/components.css`)

## Requirements
Node.js 20 or newer (tested on Node 24) and npm.

## Run it

```bash
npm install
npm run dev          # development server → http://localhost:5173
```

```bash
npm run build        # production build → dist/
npm run preview      # serve dist/ locally → http://localhost:4173
```

## Project layout

```
index.html, packages.html, gallery.html, animals/*.html   ← GENERATED by `npm run pages` — do not edit by hand
data/site.mjs          ← business facts: packages, rates, inclusions, contact details, lodge copy, species→photo map
data/species.raw.json  ← species copy & trophy fees (from the original site)
data/gallery.raw.json  ← gallery items, captions, categories
data/media-manifest.json ← written by the image pipeline (sizes, widths, colours)
scripts/build-pages.mjs  ← page generator (shared header/footer, responsive <picture> markup, SEO, JSON-LD, sitemap)
scripts/optimize-media.mjs ← image + video pipeline
scripts/make-icons.mjs ← favicon, apple-touch icon, social-share image
scripts/make-hero-video.mjs ← hero film: re-encodes img/hero/herofull.mp4 (35 MB → 2 MB phone / 4 MB desktop) + poster (`npm run hero`)
src/css/  tokens.css (colours/type/spacing, both themes) · base.css · components.css · pages.css
src/js/   main.js · theme.js · header.js · scope.js · motion.js · gallery.js · home.js · form.js
img/                   ← ORIGINAL photographs and videos (never served, never modified)
public/                ← copied as-is into dist/: media/ (optimised output), logos, favicon, robots.txt, sitemap.xml
```

### Changing content
Edit `data/site.mjs` (packages, rates, contact details) or `data/species.raw.json` (species copy and fees), then run `npm run pages` (the build does this automatically).

## Photography — how images are handled
Original files stay in `img/`. `npm run images` converts every photograph into AVIF + WebP at several widths (480–2560 px) plus one JPEG fallback, **never upscaling** and keeping quality high (AVIF q62 4:4:4, WebP q84, JPEG q86 mozjpeg). Pages use `<picture>` with `srcset`/`sizes`, explicit `width`/`height` (no layout shift), lazy loading below the fold and `fetchpriority="high"` on the hero. The gallery lightbox always loads the 1920/2560 px renditions, never thumbnails.

To add or replace a photograph: drop the original in `img/…`, add it to `data/site.mjs` / the gallery data, run `npm run images` then `npm run pages`.
Videos (`.mov`) are re-encoded to web MP4 (H.264, short side ≤ 720 px, faststart) with a poster frame.

### Species that still need better photographs
Only the species listed in `speciesPhotos` (kudu, giraffe, zebra, blue wildebeest, waterbuck, eland, blesbok, buffalo, impala, nyala) have usable high-resolution photographs. The remaining ten (baboon, duiker, oryx, red hartebeest, red lechwe, roan, sable, springbuck, steenbok, warthog) exist only as ~363 px images, so they are displayed at (never above) that size. Supplying the original files — 2000 px wide or more — and re-running `npm run images && npm run pages` upgrades those pages automatically once they are mapped in `speciesPhotos`.

## Enquiry form
No backend is needed. By default the form validates and then opens the visitor's email app with the enquiry pre-written to `ripleysafaris@gmail.com`. To receive submissions directly instead, create a form endpoint (e.g. Formspree) and set:

```bash
VITE_FORM_ENDPOINT=https://formspree.io/f/xxxxxxxx   # in a .env.production file or your host's environment settings
```

## Environment variables
| Variable | When | Purpose |
|---|---|---|
| `SITE_URL` | `npm run build` | The live address, e.g. `https://www.example.com`. Enables canonical URLs, absolute Open Graph URLs, `sitemap.xml` and the sitemap line in `robots.txt`. |
| `VITE_FORM_ENDPOINT` | `npm run build` | Optional form-handling endpoint (see above). |

Example: `SITE_URL=https://www.example.com npm run build` (PowerShell: `$env:SITE_URL="https://www.example.com"; npm run build`).

## Deployment
`npm run build` creates `dist/`. Upload its contents to any static host (Netlify, Cloudflare Pages, Vercel, GitHub Pages, cPanel/Apache, Nginx). URLs are relative, so it also works from a sub-folder. Recommended: serve `/assets/*` and `/media/*` with long-lived caching (`Cache-Control: public, max-age=31536000, immutable`); asset file names contain content hashes (`/media/*` files are not hashed — if you replace one, keep the name unchanged only if a short cache is acceptable, or rename it).

## Accessibility & motion
Skip link, visible focus states, semantic landmarks, labelled form controls with live error messages, focus-trapped menu and lightbox, `prefers-reduced-motion` respected everywhere (all content remains visible and usable without animation), colour contrast checked in both themes.
The scope cursor appears only for fine pointers, hides over text fields and when Tab is pressed, and never intercepts clicks.

| Page | Perf | A11y | Best practices | SEO | LCP (simulated) | CLS | TBT |
|---|---|---|---|---|---|---|---|
| Home (video hero + species cards) | 100 | 100 | 100 | 100 | 0.9 s | 0.001 | 60 ms |
| Packages | 98 | 100 | 100 | 100 | 2.3 s | 0.002 | 20 ms |
| Gallery | 97 | 100 | 100 | 100 | 2.5 s | 0 | 30 ms |
| Species (kudu / sable) | 98 / 100 | 100 | 100 | 100 | 2.4 s / 1.9 s | 0 | ≤10 ms |

Home on the desktop profile: Performance 100, LCP 0.3 s. The *observed* (unthrottled, local) LCP was ≈0.2–0.3 s on every page; Lighthouse's simulated figure is higher because it models a slow network. Non-critical imagery (gallery tiles, decorative backgrounds) is deliberately downloaded only after the page has loaded (`src/js/defer.js`, with a `<noscript>` fallback) so it can never compete with the hero photograph. These are lab numbers on a local server — real-user (field) Core Web Vitals must be measured after deployment (e.g. PageSpeed Insights / Search Console). INP was not measurable in a lab run; all interaction handlers are lightweight (no long tasks in the trace, TBT ≤ 20 ms).

## Review tip
Add `?nomotion` to any URL (e.g. `index.html?nomotion`) to view the page with all entrance/scroll animation switched off.

## Known limitations / needs from the owner
* **Photography:** ten species have only ~363 px originals (see above) — please supply the full-size files.
* **Domain:** set `SITE_URL` at build time to enable canonical URLs, absolute Open Graph URLs and the sitemap.
* **Social links:** the original site only had WhatsApp, so none were invented. Send Facebook / Instagram URLs and they can be added to the footer.
* **Hero video:** the home-page hero background is the supplied clip. It is portrait (1080×1920): phones get a 720 px version at native 9:16; tablets/desktops get a 1080 px version cropped to a horizontal slice, so on very large monitors it is upscaled and looks soft. It is silent, loops, starts after the page has loaded and shows a still poster (with a play button) on data-saver / 2G connections or with reduced motion. Landscape 1080p+ footage would look noticeably sharper full-width — drop it in `img/hero/`, update `scripts/make-hero-video.mjs` and run `npm run hero`.
* **`public/media` (≈135 MB) and `dist/`:** the optimised photographs are generated from `img/`. Commit `public/media` if you want deployments not to re-run `npm run images` (slow: AVIF encoding).
